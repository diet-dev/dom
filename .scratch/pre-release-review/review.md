## Второй проход (после фиксов R1–R11, N1–N8)

Свежими глазами по изменённому коду + зоны, недокрытые в первый раз. Пробы: 13 сценариев, все подтверждены эмпирически.

### Новые находки

- **S1 (низкий, код). `children` как проп превращается в мусорный атрибут.** [x] ИСПРАВЛЕНО — `normalizeKey` игнорирует `children` наравне с `key` (`src/h.ts`); дети из props-объекта не рендерятся и атрибут не ставится. Регрессия: `test/props.test.ts`. `h("div", { children: ["a","b"] })` → `<div children="a,b">`. JSX безопасен (достаёт children из props), ловушка только для прямых вызовов `h()`/фабрик.
- **S2 (низкий, код). `setupControlled` не фильтрует `false` для `value`.** `input({ value: false, onChange })` — при сбросе ввода поле показывает строку `"false"` (setupControlled хранит `String(false)`), хотя при применении `false` очищает value. Асимметрия с R8. Фикс: пропускать `false` как «не задано» (`checked: false` при этом валиден).
- **S3 (низкий, док). Signal/computed, возвращающий массив, рендерится как `"a,b"`.** `div(signal(["a","b"]))` → текст "a,b" — та же семья, что `0`/`NaN`. Добавить предупреждение в доки рядом с falsy-детьми.
- **S4 (низкий, док). Смена `type` после применения `onChange` не переносит слушатель.** Событие для `onChange` выбирается на момент применения пропсов; `applyProps(el, { type: "checkbox" })` позже не перевесит слушатель с `input` на `change`. Добавить в «Ограничения».
- **S5 (наблюдение, без фикса). Исключение в `render` списка прерывает reconcile на середине.** DOM остаётся на предыдущем состоянии, эффект жив, следующий reconcile стартует со старых entries — консистентно и приемлемо для ошибки пользовательского кода.
- **S6 (решение владельца). Публичный API экспортирует недокументированные внутренности:** `applyProp`, `appendChildren`, тип `ListEntry`. `applyProps` теперь задокументирован (режим 2 форм). Варианты: убрать лишние из `index.ts` (пакет ещё не публиковался — безопасно) или задокументировать.

## Критические (блокеры релиза)

### R1. `list()` внутри Fragment крашится: `NotFoundError` — [x] ИСПРАВЛЕНО

Фикс: эффект списка привязан к якорному комментарию (`bind(anchor, ...)`), родитель выводится из `anchor.parentNode` на каждом запуске (`src/list.ts`). Якорь переживает растворение Fragment и достижим для `unmount`. Регрессия: `test/fragment-cleanup.test.ts`.

`list` как ребёнок Fragment (в JSX — `<>`): первый reconcile вставляет узлы во фрагмент, вставка в DOM растворяет его, а эффект списка замкнут на мёртвый фрагмент (`src/list.ts:25` — `bind(parent, ...)`, где `parent` — фрагмент). Любое изменение `source` после этого → `parent.insertBefore(node, anchor)` с anchor, не лежащим в `parent` → **runtime crash**.

Воспроизведение (проверено):

```ts
const frag = jsxs(Fragment, { children: [list(source, k, r)] });
const host = div();
host.append(frag);
source.value = [...source.value, "b"]; // NotFoundError: The child can not be found in the parent
```

Сценарий реален: оборачивание куска разметки в `<>` — идиома. Даже без обёртки: `<div><>{list(...)}</></div>`.

### R2. Fragment + signal-ребёнок: эффект переживает `unmount` — [x] ИСПРАВЛЕНО

Фикс: `bindChildSignal` держит маркер в DOM постоянно и вставляет контент перед ним; эффект привязан к маркеру (`src/h.ts`). Маркер переезжает в реального родителя при растворении Fragment и достижим для `unmount`.

`bindChildSignal` привязывает эффект к родителю (`src/h.ts:245`); если родитель — фрагмент, после растворения эффект недостижим для `unmount`. Проверено: после `unmount(host)` изменение сигнала продолжает патчить DOM узла. Утечка подписки + работа вхолостую.

Тот же класс проблемы: `component()`/компонент, возвращающий `<>` с сигналами внутри.

### R3. `Fragment` не экспортирован из корня — README и LEARN учат неверному импорту — [x] ИСПРАВЛЕНО

Фикс: `export { Fragment } from "./jsx-runtime.ts"` в `src/index.ts` (циклических импортов нет).

### R4. Нет LICENSE — npm-блокер — [x] ИСПРАВЛЕНО

Фикс: добавлен `LICENSE` (MIT) и поле `"license": "MIT"` в `package.json`.

## Высокие

### R5. Дубли ключей в `list()` оставляют зомби-узлы — [x] ИСПРАВЛЕНО

Фикс: первый ключ выигрывает, повторы пропускаются с однократным `console.warn` на ключ (`src/list.ts`, поле `#dupesWarned`). Регрессия: `test/list.test.ts` («дубли ключей»).

### R6. Controlled-режим 2 (plain value + onChange) замораживает поле навсегда — [x] ИСПРАВЛЕНО (документация)

Честного React-поведения без ререндера не воспроизвести, поэтому контракт переименован и задокументирован как есть: «уведомляемое read-only» — ввод сбрасывается к стартовому пропсу, обработчик получает событие, автопереприменения нет (только повторный `applyProps`). README и LEARN обновлены.

### R7. Signal-обновления `dataset` и `style`-объекта накапливают устаревшие данные — [x] ИСПРАВЛЕНО

Фикс: `applyProp` стирает предыдущее состояние перед применением объекта — `dataset` очищает старые ключи, `style` сбрасывает `cssText` (`src/h.ts`). Семантика: значение пропса описывает состояние целиком. Заодно закрыта дыра типизации — `style` теперь принимает `Signal`. Регрессия: `test/props.test.ts`.

## Средние

### R8. `false` в пропсах становится мусорным атрибутом — [x] ИСПРАВЛЕНО

Фикс: `false` трактуется как «не задано» (clear/skip) во всех пропсах; не-функции в `on*` игнорируются (`src/h.ts`, `applyProp`). Типы `Props` расширены (`on*` и `class` допускают `false`). Регрессия: `test/props.test.ts`. Проверено: `div({ onClick: false })` → `<div></div>`.

### R9. Falsy-дети: `0` и `NaN` рендерятся как текст — нигде не задокументировано — [x] ИСПРАВЛЕНО (документация)

README («Дети») и LEARN (раздел 4) теперь явно предупреждают про `count && node` при `count = 0`. Регрессия: `test/h.test.ts`.

### R10. Signal-ребёнок c Node: заменённый узел не диспозится — [x] ИСПРАВЛЕНО

Фикс: `bindChildSignal` диспозит заменяемый узел через `unmount` (эффекты поддерева + удаление из DOM, `src/h.ts`). Документировано в README и LEARN. Регрессия: `test/bind.test.ts`.

### R11. `ListView.mount()` без защиты от повторного вызова — [x] ИСПРАВЛЕНО

Фикс: повторный `mount` бросает `Error("ListView is already mounted")` (`src/list.ts`). Регрессия: `test/list.test.ts`.
